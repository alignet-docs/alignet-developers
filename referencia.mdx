## Estados de transacción

Los estados por los que puede pasar una transacción en el flujo de PayIn:

| Estado | Descripción |
| :-- | :-- |
| `REGISTRADO` | La transacción se registró correctamente en la pasarela. |
| `PENDIENTE` | Enviada al procesador — en espera de respuesta o de que el usuario complete el pago. |
| `AUTORIZADO` | El procesador aprobó la transacción y los fondos están reservados. |
| `DENEGADO` | El procesador rechazó la transacción — fondos insuficientes, datos incorrectos u otro motivo. |
| `INVALIDO` | La transacción fue invalidada por reglas de negocio o error de procesamiento. |
| `CANCELADO` | El usuario o el comercio cancelaron la transacción antes de su liquidación. |
| `EXPIRADO` | La transacción superó el tiempo límite sin completarse. |
| `LIQUIDADO` | La transacción fue enviada al procesador para su liquidación final. |
| `DEVUELTO` | La devolución fue enviada al procesador para reversión de fondos. 🔜 Próximamente |
| `ABONADO` | El monto será acreditado en la cuenta del comercio. 🔜 Próximamente |

## Códigos de respuesta

Códigos retornados en el campo `meta.status.code` de todas las respuestas de PayIn:

| Código | Descripción |
| :-- | :-- |
| `00` | Se procesó correctamente la petición |
| `01` | Transacción rechazada por el procesador |
| `02` | La transacción expiró |
| `03` | Ocurrió un error |
| `04` | No se pudo procesar la petición |
| `05` | No se encontró el pedido |
| `06` | Algunos datos no fueron enviados correctamente |
| `07` | Comercio no existente |
| `08` | Comercio requiere configuración de procesamiento |
| `09` | Método de pago no soportado |
| `10` | Se requiere un token de acceso |
| `11` | Token de acceso inválido |
| `12` | La operación se encuentra finalizada |
| `13` | La operación se encuentra en proceso |
| `14` | Usuario regresó al comercio sin seleccionar método de pago |
| `15` | Usuario canceló la transacción y regresó al comercio |
