## Matriz de responsabilidades

| Área | SCC o sistema de caja | Pay-me PinPAD / Alignet | Validación conjunta |
| --- | --- | --- | --- |
| Red local | Alcanzar la IP y el puerto del terminal; configurar firewall y timeout. | Exponer el servidor HTTP en el Wiseasy P5L. | Ejecutar `GET /health` desde el SCC. |
| Operación | Calcular el monto, generar y persistir `operationNumber` y aplicar la decisión del carril. | Validar la solicitud, ejecutar el cobro y devolver el resultado. | Probar aprobación, rechazo, cancelación y recuperación. |
| Idempotencia | Mantener una sola referencia por operación real y consultar ante incertidumbre. | Evitar un segundo cargo para la misma referencia y conservar el resultado. | Simular timeout, reenvío y consulta. |
| Concurrencia | Serializar solicitudes destinadas al mismo terminal. | Procesar una operación a la vez y devolver `409 POS_BUSY` a otra referencia. | Enviar solicitudes concurrentes controladas. |
| Configuración | Registrar IP, puerto y asociación entre SCC, carril y terminal. | Instalar la aplicación, configurar IP/puerto y verificar llaves. | Confirmar el estado **Listo para el siguiente vehículo**. |
| Seguridad | Proteger la red, los logs y los datos de conciliación. | No exponer datos sensibles de tarjeta en la respuesta. | Revisar evidencias sanitizadas. |
| Soporte | Conservar solicitudes, respuestas, códigos HTTP y marcas de tiempo. | Correlacionar la operación y apoyar el diagnóstico. | Definir responsables y escalamiento. |

## Preparación del SCC

### Cliente HTTP

- Implementa `GET /health`, `POST /authorize` y `GET /payments/{operationNumber}`.
- Envía `Content-Type: application/json` en la autorización.
- Configura al menos 100 a 110 segundos de timeout para `POST /authorize`.
- Lee el código HTTP, el cuerpo JSON y `Retry-After` cuando esté disponible.
- Maneja `200`, `202`, `400`, `404`, `409` y `503` según la operación.
- Mantén una cola o bloqueo por terminal para no enviar cobros concurrentes.

### Estado transaccional

- Persiste la referencia y los datos del cobro antes del envío.
- Confirma solo `status: "APPROVED"` junto con `resultCode: "00"`.
- Conserva como abiertas las operaciones `PENDING`, `PROCESSING` o `UNKNOWN`.
- Recupera las operaciones abiertas después de un reinicio del SCC.
- No conviertas un timeout o `404` de consulta en rechazo financiero.

### Operación del carril

- Define cuándo abrir la barrera y cómo informar rechazo o cancelación.
- Define el límite de espera y el escalamiento de una operación no resuelta.
- Crea un nuevo `operationNumber` para un nuevo intento después de un resultado final `DENIED` o `CANCELLED`.
- Conserva `authorizationCode` y `operationNumber` para el comprobante y la conciliación.

## Preparación del Wiseasy P5L

Alignet y el operador deben:

- instalar la versión de Pay-me PinPAD correspondiente al package `com.alignet.pinpad.ecr`;
- conectar el terminal a la red local y asignarle una IP estable;
- configurar la IP y el puerto de escucha, cuyo valor predeterminado es `8080`;
- confirmar la llamada real de `GET /health` desde el SCC;
- completar la verificación de inyección de llaves;
- dejar la aplicación en **Listo para el siguiente vehículo**;
- confirmar que el terminal dispone de la conectividad necesaria para procesar el pago.

## Checklist de inicio

<Check>
  El SCC y el Wiseasy P5L están en la misma red local y sin aislamiento entre clientes.
</Check>

<Check>
  La IP del terminal es fija o tiene una reserva DHCP.
</Check>

<Check>
  `GET /health` responde HTTP `200` desde el equipo donde se ejecuta el SCC.
</Check>

<Check>
  El SCC genera y persiste un `operationNumber` válido y único por cobro.
</Check>

<Check>
  El monto se representa como entero positivo en unidades menores.
</Check>

<Check>
  El cliente maneja la consulta, idempotencia, concurrencia y reinicios.
</Check>

<Check>
  La política del carril está definida para todos los estados finales y no finales.
</Check>

<Check>
  Los logs de pruebas no contienen información sensible de tarjeta.
</Check>
