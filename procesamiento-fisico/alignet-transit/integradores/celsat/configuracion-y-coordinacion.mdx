La integración mantiene un contrato funcional estable y desacopla los valores que pueden ajustarse durante la habilitación del ambiente.

## Elementos estables

Los siguientes elementos forman parte de la especificación de integración:

| Elemento | Definición |
| --- | --- |
| Arquitectura | SCC → LAN → Componente Local en P5L → PaymePOS SDK → SDK del dispositivo → plataforma de pagos. |
| Autorización | `POST /api/v1/payments`. |
| Consulta | `GET /api/v1/payments/{operationNumber}`. |
| Formato | JSON con `Content-Type` y `Accept` en `application/json`. |
| Solicitud | `operationNumber`, `amount` y `currency` como campos requeridos; `additionalFields` como objeto opcional. |
| Información adicional | `montoPeaje`, `montoDetraccion` e `IdTurnoVia`, asociados y retornados con la operación. |
| Respuesta | `success`, `resultCode`, `resultMessage` y `result`. |
| Aprobación | `result.state = "AUTORIZADO"`. |
| Correlación | `operationNumber` de CELSAT y `transactionID` de Alignet. |
| Recuperación | Consultar la referencia original después de timeout o pérdida de comunicación. |

## Parámetros sujetos a validación final

| Parámetro | Tratamiento |
| --- | --- |
| URL base del ambiente | Por confirmar durante la habilitación final. |
| Mecanismo de autenticación | Pendiente de confirmación en ambiente de integración. |
| Timeout de conexión y lectura | Parámetro sujeto a ajuste durante las pruebas de integración. |
| Frecuencia y límite de consulta | Parámetro sujeto a ajuste durante las pruebas de integración. |
| Direccionamiento del P5L en la LAN | Por confirmar para cada terminal y ambiente. |
| Asociación SCC–P5L | Se valida durante la preparación del carril o laboratorio. |
| Política de soporte y escalamiento | Se entrega como parte de la habilitación operativa. |

<Info>
  Los ajustes de estos parámetros no modifican los endpoints, los mensajes, los estados ni las responsabilidades principales de la solución.
</Info>

## Ambientes

| Ambiente | Finalidad | Condición de uso |
| --- | --- | --- |
| Integración | Validar conectividad, contrato y comportamiento técnico. | Utiliza terminales y datos controlados. |
| UAT | Validar el flujo completo del carril con CELSAT. | Requiere evidencia y criterios de aceptación conjuntos. |
| Producción | Procesar operaciones de los carriles habilitados. | Se habilita después de completar las validaciones acordadas. |

## Artefactos de habilitación

<Steps>
  <Step title="Especificación de interfaz">
    Contiene endpoints, mensajes, tipos, estados y códigos confirmados.
  </Step>
  <Step title="Ficha del ambiente">
    Registra URL base, mecanismo de autenticación, timeouts y terminales asignados.
  </Step>
  <Step title="Plan de pruebas">
    Define escenarios, datos, evidencias y criterios de aceptación.
  </Step>
  <Step title="Procedimiento de soporte">
    Define contactos, severidades, información de diagnóstico y escalamiento.
  </Step>
</Steps>

## Control de cambios

Cada ajuste debe identificar versión, ambiente y fecha de vigencia. Un cambio en endpoints, campos, tipos, estados o semántica requiere actualizar la especificación versionada. Un ajuste de URL, timeout o asignación de terminal se gestiona en la ficha del ambiente.
