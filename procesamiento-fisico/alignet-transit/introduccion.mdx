**Pay-me Transit PinPAD** permite iniciar y recuperar pagos desde un **Sistema de Control de Carril (SCC)** o sistema de caja. La integración utiliza HTTP/JSON sobre la red local.

Esta documentación corresponde a la aplicación **Pay-me PinPAD** con package `com.alignet.pinpad.ecr`, instalada en el terminal **Wiseasy P5L**.

<Info>
  En esta integración, el **cliente HTTP** es el SCC o sistema de caja. El **servidor HTTP** es la aplicación Pay-me PinPAD instalada en el Wiseasy P5L.
</Info>

## Qué debes implementar

| Operación | Método y ruta | Finalidad |
| --- | --- | --- |
| Verificar disponibilidad | `GET /health` | Confirmar que la aplicación está abierta y accesible. |
| Autorizar un pago | `POST /authorize` | Iniciar un cobro y esperar su resultado en la misma conexión. |
| Consultar una operación | `GET /payments/{operationNumber}` | Recuperar el resultado después de un estado pendiente, timeout o pérdida de conexión. |
| Cancelar o extornar | `POST /reversals` | Interrumpir una autorización en curso o revertir totalmente una venta aprobada, según su estado actual. |
| Consultar una cancelación o extorno | `GET /reversals/{operationNumber}` | Recuperar el resultado de la solicitud pendiente o incierta. |

El contrato no requiere instalar una librería en el SCC. Debes implementar un cliente HTTP capaz de enviar y recibir JSON, mantener abierta la solicitud de autorización y recuperar operaciones inciertas.

## Flujo en cinco pasos

<Steps>
  <Step title="Comprobar conectividad">
    Ejecuta `GET /health`. Durante la configuración inicial, esta llamada también permite que Pay-me PinPAD confirme que el SCC alcanza el terminal.
  </Step>
  <Step title="Crear la referencia">
    Genera y persiste un `operationNumber` único antes de iniciar el cobro.
  </Step>
  <Step title="Enviar la autorización">
    Ejecuta `POST /authorize` con el monto en unidades menores. Configura un timeout HTTP de al menos 100 a 110 segundos.
  </Step>
  <Step title="Interpretar el resultado">
    Confirma el pago únicamente si recibes HTTP `200`, `status: "APPROVED"` y `resultCode: "00"`.
  </Step>
  <Step title="Recuperar un resultado incierto">
    Ante HTTP `202`, timeout o pérdida de conexión, consulta `GET /payments/{operationNumber}`. No inicies otro cobro.
  </Step>
</Steps>

## Principios de implementación

- Una operación real de cobro utiliza un único `operationNumber`.
- `amount` representa un entero positivo en unidades menores. Por ejemplo, `1500` equivale a S/ 15.00.
- El cobro es síncrono. `POST /authorize` permanece abierto mientras el usuario presenta la tarjeta e ingresa el PIN cuando corresponde.
- `PENDING` y `UNKNOWN` no significan rechazo. Debes consultar antes de tomar una decisión o iniciar otro cobro.
- Pay-me PinPAD procesa una operación a la vez. Una referencia diferente recibida durante un cobro activo obtiene `409 POS_BUSY`.
- La cancelación detiene una autorización activa; el extorno revierte una venta que ya fue aprobada. No intercambies estos flujos.
- El SCC no recibe PAN completo, CVV, PIN, PIN Block, pistas ni datos EMV sensibles.
