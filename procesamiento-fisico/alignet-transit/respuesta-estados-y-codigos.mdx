Interpreta el HTTP, `status` y `resultCode` según el endpoint. HTTP `200` o el mensaje por sí solos no confirman éxito.

Todas las respuestas incluyen `Cache-Control: no-store`. HTTP `202` añade `Retry-After: 2`.

## Estructura de respuesta de pago

Cobro, cancelación y extorno utilizan esta forma normal. El bloque describe tipos, no una respuesta de prueba:

```json
{
  "operationNumber": "string",
  "status": "string",
  "resultCode": "string|null",
  "resultMessage": "string",
  "authorizationCode": "string|null",
  "completedAt": "string|null"
}
```

| Campo | Uso |
| --- | --- |
| `operationNumber` | Referencia de la operación. |
| `status` | Estado de cobro, cancelación o extorno. |
| `resultCode` | Código SDK conservado o código propio de la app. |
| `resultMessage` | Mensaje recibido; no sustituye la interpretación del estado y código. |
| `authorizationCode` | Código de autorización o `null`. |
| `completedAt` | Fecha UTC en formato `yyyy-MM-dd'T'HH:mm:ss'Z'`, solo cuando la operación terminó; en espera es `null`. |

Extorno `UNKNOWN` con HTTP `502` utiliza una forma compacta distinta:

```json
{
  "operationNumber": "string",
  "status": "UNKNOWN",
  "message": "string"
}
```

Esta forma no incluye `resultCode`, `resultMessage`, `authorizationCode` ni `completedAt`. La clave del mensaje es `message`.

## Respuestas de `POST /authorize`

| HTTP | `status` | `resultCode` | Acción |
| --- | --- | --- | --- |
| `200` | `APPROVED` | `00` | Confirmar el pago y ejecutar la acción de negocio. |
| `200` | `DENIED` | Código SDK | Cerrar el cobro como no aprobado. |
| `202` | `PROCESSING`, `PENDING`, `UNKNOWN` | `PROCESSING`, `WAITING_RESULT`, `UNKNOWN` | Esperar dos segundos y consultar el cobro con la misma referencia. |
| `400` | `ERROR` | `BAD_REQUEST` | Corregir JSON o monto fuera del límite. |
| `409` | `ERROR` | `POS_BUSY` | Esperar a que termine la operación activa. |
| `503` | `ERROR` | `POS_NOT_AVAILABLE` | Restablecer SDK o pantalla disponible antes de reintentar. |

HTTP `202` puede corresponder a una solicitud duplicada aún en curso, al tiempo de espera agotado o al control de tiempo del servicio. No inicies otro cobro.

## Consulta de estado

`GET /payments/{operationNumber}` consulta **el cobro original**, no el resultado de `/cancel`.

| HTTP | Resultado | Acción |
| --- | --- | --- |
| `200` | Resultado guardado con `APPROVED`, `DENIED`, `CANCELLED` o `ERROR`. | Evaluar estado y código; un error no confirma aprobación. |
| `202` | `PROCESSING`, `PENDING` o `UNKNOWN`. | Seguir consultando con `Retry-After: 2`, sin otro cobro. |
| `404` | `ERROR/NOT_FOUND` | Verificar referencia y terminal; no asumir rechazo financiero. |
| `400` | `ERROR/BAD_REQUEST` | Corregir el segmento vacío o inválido de la ruta. |

## Estados

| Operación | Sigue esperando un resultado | La solicitud terminó |
| --- | --- | --- |
| Cobro y cancelación (`PaymentStatus`) | `PROCESSING`, `PENDING`, `UNKNOWN` | `APPROVED`, `DENIED`, `CANCELLED`, `ERROR` |
| Extorno (`ReversalStatus`) | `SEARCHING`, `PROCESSING`, `PENDING` | `REVERSED`, `DENIED`, `UNKNOWN`, `ERROR` |

En la forma normal, `completedAt` se informa solo en los estados de la última columna. Un estado `ERROR` significa que terminó con error, no que hubo éxito.

`UNKNOWN` en cobro devuelve HTTP `202`: todavía no se sabe si se cobró y debes seguir consultando. En extorno devuelve HTTP `502` con el cuerpo compacto: revisa si se ejecutó con Alignet, sin asumir éxito ni reenviar automáticamente.

## Códigos confirmados

### Mapeo de códigos SDK

| Código SDK | Cobro | Cancelación | Extorno CARD |
| --- | --- | --- | --- |
| `00` | `APPROVED` | `CANCELLED` | `REVERSED` |
| `16`, `17` | `DENIED` | `CANCELLED`, éxito equivalente | `REVERSED`, éxito equivalente |
| `P22` | `DENIED` | `PENDING` | `PENDING` |
| `05`, `07` | `DENIED` | HTTP `404` | HTTP `404` |
| `14`, `15`, `18`, `19`, `20`, `01`, `03` y otros | `DENIED` | `DENIED` | `DENIED` |

Conserva los códigos SDK; no los reemplaces por `00` ni por un código inventado. Si el SDK devuelve un código vacío, la app utiliza el nombre del `status`, por ejemplo `DENIED` o `APPROVED`.

### Códigos propios de la app

| Código | Significado |
| --- | --- |
| `BAD_REQUEST` | JSON, campos o segmento de ruta inválidos. |
| `NOT_FOUND` | Operación o ruta no encontrada. |
| `POS_NOT_AVAILABLE` | SDK no listo o pantalla no disponible. |
| `POS_BUSY` | Terminal ocupado. |
| `CANCELLATION_IN_PROGRESS` | Ya existe una cancelación en curso para esa referencia. |
| `PROCESSING`, `SEARCHING` | Operación o búsqueda en curso. |
| `WAITING_RESULT` | Tiempo de espera agotado, sin resultado confirmado. |
| `UNKNOWN` | Resultado desconocido; su HTTP y cuerpo dependen de la operación. |
| `METHOD_NOT_ALLOWED` | Ruta válida con método HTTP incorrecto. |

## Matriz de decisión

| Endpoint | Qué informa | Acción |
| --- | --- | --- |
| `POST /authorize` | Resultado del cobro. | Confirmar únicamente `APPROVED/00`. |
| `GET /payments/{operationNumber}` | Estado del cobro original. | Consultar ante espera, timeout o incertidumbre. |
| `POST /cancel` | Resultado de esa solicitud de cancelación. | Éxito solo con `CANCELLED` y `00`, `16` o `17`, validado por el servicio. `DENIED/14` no confirma cancelación. |
| `POST /reversals` | Resultado de un extorno CARD independiente. | Éxito con `REVERSED` y `00`, `16` o `17`. |
| `GET /reversals/{operationNumber}` | Resultado del extorno CARD. | Consultar cuando corresponda; HTTP `502 UNKNOWN` exige revisión. |

Una ruta válida con método incorrecto devuelve HTTP `405` y `METHOD_NOT_ALLOWED`. Una ruta desconocida devuelve HTTP `404` y `NOT_FOUND`.

## Consulta después de cancelar

No existe un endpoint de consulta de cancelación: su desenlace se devuelve solo en `POST /cancel`. Si confirma una cancelación validada, no exige otro GET para reconocerla.

Ante fallo, timeout o incertidumbre, consulta el cobro original y aplica la [decisión por método](/procesamiento-fisico/alignet-transit/cancelacion#verificar-el-resultado-final). Un pago CARD aprobado permite evaluar un extorno independiente; un pago QR aprobado se conserva sin devolución.

No sustituyas un resultado confirmado por un `202 PENDING` tardío ni uses el cierre de pantalla como prueba de cancelación.
