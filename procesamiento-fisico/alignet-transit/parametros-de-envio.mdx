El sistema central del comercio inicia un pago mediante una solicitud HTTP a Pay-me PinPAD. `POST /authorize` es síncrono: la conexión permanece abierta mientras el terminal procesa la operación y devuelve el resultado.

```http
POST /authorize
Content-Type: application/json
```

Construye la URL con la dirección IP y el puerto configurados en el terminal:

```text
http://<IP_DEL_PINPAD>:<PUERTO>/authorize
```

## Solicitud mínima

Envía los cuatro campos obligatorios en el cuerpo JSON:

```json
{
  "operationNumber": "44992528",
  "amount": "100",
  "currency": "604",
  "paymentMethod": "QR"
}
```

## Parámetros

| Campo              | Tipo JSON | Obligatorio | Validación                                                                                          | Descripción                                                                                                          |
| ------------------ | --------- | ----------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `operationNumber`  | String    | Sí          | Cadena numérica de 6 a 12 dígitos.                                                                  | Identificador único generado por el sistema central. Se utiliza como clave de idempotencia y referencia de consulta. |
| `amount`           | String    | Sí          | Cadena numérica que representa un entero positivo de 1 a 12 dígitos, expresado en unidades menores. | Importe total del pago. Por ejemplo, `"1500"` representa S/ 15.00.                                                   |
| `currency`         | String    | Sí          | Cadena numérica de exactamente 3 dígitos.                                                           | Código numérico ISO 4217 de la moneda. Para soles peruanos, envía `"604"`.                                           |
| `paymentMethod`    | String    | Sí          | Debe contener un único valor: `CARD` o `QR`.                                                        | Método con el que Pay-me PinPAD procesará el pago.                                                                   |
| `tollData`         | Object    | No          | Sus campos deben enviarse como String.                                                              | Datos de la operación de peaje. Pueden enviarse para fines de trazabilidad.                                          |
| `additionalFields` | Object    | No          | Todos los valores deben ser String.                                                                 | Información complementaria asociada al pago.                                                                         |

Respeta los nombres, los tipos JSON y el uso de mayúsculas de cada campo. Por ejemplo, envía `paymentMethod`, no `payment_method`.

## Detalle de los parámetros

### `operationNumber`

Genera un `operationNumber` nuevo para cada pago y almacénalo antes de llamar a `POST /authorize`. El valor debe cumplir estas condiciones:

* ser una cadena de entre 6 y 12 dígitos;
* contener únicamente dígitos del `0` al `9`;
* ser único para una operación real de pago;
* permanecer asociado a la operación hasta obtener un resultado final.

Si no recibes el resultado por un timeout o una pérdida de conexión, conserva la referencia original. Utilízala para consultar la operación o para reenviar exactamente la misma solicitud.

<Warning>
  No generes otro `operationNumber` después de un timeout. La solicitud original puede haber producido un cargo.
</Warning>

### `amount`

Expresa el importe en unidades menores, sin símbolo de moneda, separadores ni decimales:

| Importe   | Valor válido de `amount` |
| --------- | -----------------------: |
| S/ 1.00   |                  `"100"` |
| S/ 8.50   |                  `"850"` |
| S/ 15.00  |                 `"1500"` |
| S/ 125.40 |                `"12540"` |

Envía `amount` como String. No utilices números JSON, valores decimales, signos, espacios ni separadores.

### `currency`

Envía `currency` como un String de tres dígitos que contenga el código numérico ISO 4217 de la moneda.

Para pagos en soles peruanos, utiliza `"604"`. Confirma con Alignet cualquier moneda distinta de PEN antes de habilitarla en producción.

### `paymentMethod`

Envía exactamente uno de los siguientes valores en mayúsculas:

| Valor  | Método de pago               |
| ------ | ---------------------------- |
| `CARD` | Tarjeta de crédito o débito. |
| `QR`   | Código QR.                   |

Cada solicitud admite un solo método de pago. No envíes `CARD` y `QR` juntos, arreglos, valores combinados como `"CARD,QR"`, variantes como `card` o `qr`, ni valores diferentes de los documentados.

### `tollData`

Utiliza `tollData` para enviar datos de la operación de peaje con fines de trazabilidad. El objeto y todos sus campos son opcionales.

| Campo                 | Tipo JSON | Obligatorio | Descripción                                                                                                                               |
| --------------------- | --------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `shiftId`             | String    | No          | Identificador del turno y la vía. Su formato se acuerda para cada integración; no existe una composición única para todos los operadores. |
| `tollOperatorId`      | String    | No          | Identificador del operador del peaje.                                                                                                     |
| `tollPointId`         | String    | No          | Identificador del punto de peaje.                                                                                                         |
| `laneId`              | String    | No          | Identificador de la vía o carril.                                                                                                         |
| `transactionDateTime` | String    | No          | Fecha y hora de la operación en formato ISO 8601, con zona horaria.                                                                       |
| `plate`               | String    | No          | Placa del vehículo.                                                                                                                       |
| `tollAmount`          | String    | No          | Importe del peaje expresado en unidades menores.                                                                                          |
| `withholdingAmount`   | String    | No          | Importe de la retención expresado en unidades menores.                                                                                    |
| `direction`           | String    | No          | Sentido de circulación.                                                                                                                   |
| `vehicleClass`        | String    | No          | Categoría del vehículo.                                                                                                                   |
| `axleCount`           | String    | No          | Número de ejes.                                                                                                                           |

Cuando envíes los importes de peaje y retención, deben cumplir esta relación:

```text
amount = tollAmount + withholdingAmount
```

#### Interpretación de `shiftId` para reportes

El formato de `shiftId` se acuerda para cada integración. Por ejemplo, si el formato acordado es `punto + vía + turno + fecha operativa (AAAAMMDD)`, el valor ilustrativo `AB2N20260710` se interpreta así:

| Componente | Valor | Significado |
| --- | --- | --- |
| Punto | `AB` | Debe coincidir con `tollPointId`. |
| Vía | `2` | Debe coincidir con `laneId`. |
| Turno | `N` | Código del turno según la convención acordada. |
| Fecha operativa | `20260710` | Fecha asociada al turno en formato `AAAAMMDD`. |

Con la convención acordada, estos componentes pueden usarse como filtros y columnas del reporte de conciliación. **No agregues `shift` ni `shiftDate` al request**: son valores derivados de `shiftId`. Define también cómo interpretar la fecha operativa cuando un turno cruza la medianoche; puede ser distinta del día indicado por `transactionDateTime`.

Si el formato del identificador es diferente, define la regla de extracción antes de usarlo en reportes. No apliques el formato ilustrativo a todas las integraciones.

### `additionalFields`

El comercio puede declarar en `additionalFields` cualquier otro dato complementario que necesite. Los valores se envían como cadenas.

```json
{
  "additionalFields": {}
}
```

Si el comercio no necesita agregar información complementaria, puede enviar un objeto vacío u omitir `additionalFields`.

## Ejemplo de autorización para peaje

El siguiente ejemplo ilustra los datos de la operación de peaje con identificadores genéricos. El formato de `shiftId` mostrado es solo un ejemplo de composición: código del punto (`AB`) + vía (`2`) + turno (`N`) + fecha operativa (`20260710`). Cada integración debe acordar su propia convención.

```json
{
  "operationNumber": "012001000039",
  "amount": "3150",
  "currency": "604",
  "paymentMethod": "CARD",
  "tollData": {
    "shiftId": "AB2N20260710",
    "tollOperatorId": "OPERADOR_01",
    "tollPointId": "AB",
    "laneId": "2",
    "transactionDateTime": "2026-07-10T00:13:00-05:00",
    "plate": "TIY953",
    "tollAmount": "2583",
    "withholdingAmount": "567",
    "direction": "NORTH",
    "vehicleClass": "HEAVY",
    "axleCount": "3"
  },
  "additionalFields": {}
}
```

## Enviar la solicitud

Este ejemplo envía una solicitud mínima:

```bash
curl --request POST "http://<IP_DEL_PINPAD>:<PUERTO>/authorize" \
  --header "Content-Type: application/json" \
  --max-time 110 \
  --data '{
    "operationNumber": "44992528",
    "amount": "100",
    "currency": "604",
    "paymentMethod": "QR"
  }'
```

Reemplaza `<IP_DEL_PINPAD>` y `<PUERTO>` por los valores configurados en tu terminal.

## Respuestas de autorización

Cuando `POST /authorize` responde HTTP `200`, el resultado final viene en esa misma respuesta. Evalúa siempre `status` y `resultCode`.

| HTTP | Resultado | Acción del sistema central |
| --- | --- | --- |
| `200` | `APPROVED` + `00` | Confirma el pago y guarda el código de autorización. |
| `200` | `DENIED` | No confirmes el pago. Un nuevo intento requiere otro `operationNumber`. |
| `202` | `PENDING` | Conserva la referencia, respeta `Retry-After` y consulta el resultado. |
| `400` | `BAD_REQUEST` | Corrige la solicitud antes de reenviarla. |
| `409` | `POS_BUSY` | Espera a que el terminal termine la operación activa. |
| `503` | `POS_NOT_AVAILABLE` | Restablece la disponibilidad del PinPAD antes de reintentar. |

<Warning>
  Un HTTP `200` no significa necesariamente que el pago fue aprobado. Confirma únicamente `status: "APPROVED"` junto con `resultCode: "00"`.
</Warning>

## Antes de producción

Confirma las monedas y medios de pago habilitados, el soporte de `transactionDateTime`, la convención de `shiftId`, el timeout definitivo y el comportamiento de una referencia reutilizada con otro body. Si los componentes de `shiftId` se utilizarán en reportes, confirma también la regla de extracción y la fecha operativa que corresponde a los turnos que cruzan la medianoche. Consulta el registro centralizado de [Datos por validar](/procesamiento-fisico/alignet-transit/datos-por-validar).

Hasta confirmar el último punto, reenvía exactamente el mismo cuerpo cuando no hayas recibido el resultado. Para consultar su estado, utiliza el `operationNumber` original.

## Lista de verificación

Antes de enviar la solicitud, verifica lo siguiente:

* `operationNumber` está almacenado, es único y contiene únicamente entre 6 y 12 dígitos.
* `amount` es un String numérico de hasta 12 dígitos que representa un entero positivo en unidades menores.
* `currency` es un String numérico de exactamente tres dígitos.
* `paymentMethod` está presente y contiene exactamente un valor: `CARD` o `QR`, en mayúsculas.
* Si envías `tollData`, sus campos son String y los importes cumplen `amount = tollAmount + withholdingAmount`.
* `direction`, `vehicleClass` y `axleCount`, si se envían, están dentro de `tollData`.
* Si envías `transactionDateTime`, incluye la zona horaria. Si `shiftId` tiene componentes acordados, comprueba su coherencia con el punto y la vía enviados por separado.
* Todos los valores de `additionalFields`, si envías el objeto, son cadenas.
* La solicitud utiliza `Content-Type: application/json`.
* El timeout del cliente HTTP es el acordado para el ambiente.
