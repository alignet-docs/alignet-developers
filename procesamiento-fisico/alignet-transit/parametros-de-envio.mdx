El SCC de CELSAT envía la solicitud de pago al Componente Local de Integración instalado en el terminal P5L. Para iniciar una autorización, la trama requiere únicamente `operationNumber`, `amount` y `currency`.

## Campos obligatorios

| Campo | Tipo | Obligatorio | Descripción | Ejemplo |
| --- | --- | --- | --- | --- |
| `operationNumber` | String | Sí | Número único de operación generado por CELSAT. Permite correlacionar la solicitud durante todo su ciclo. | `20100008` |
| `amount` | String | Sí | Monto expresado en unidades menores, sin separador decimal. | `850` equivale a S/ 8.50 |
| `currency` | String | Sí | Código numérico ISO 4217 de la moneda. | `604` para PEN |

### Trama mínima

```json
{
  "operationNumber": "20100008",
  "amount": "850",
  "currency": "604"
}
```

<Info>
  `amount` y `currency` se envían como cadenas. Por ejemplo, S/ 8.50 se representa con `amount: "850"` y `currency: "604"`.
</Info>

## Datos adicionales

La trama admite el atributo opcional `additionalFields` para incorporar información complementaria. Este atributo contiene pares clave/valor y no agrega nuevos campos obligatorios a la autorización.

CELSAT define los nombres y valores incluidos en `additionalFields` de acuerdo con la información que decida asociar a cada operación. Alignet no establece campos adicionales obligatorios.

### Trama con datos adicionales

```json
{
  "operationNumber": "20100008",
  "amount": "850",
  "currency": "604",
  "additionalFields": {
    "<campo_definido_por_CELSAT>": "<valor>"
  }
}
```

## Estructura de la solicitud

```text
operationNumber    Obligatorio
amount             Obligatorio
currency           Obligatorio
additionalFields   Opcional
```

Antes del envío, CELSAT debe verificar que:

- `operationNumber` esté presente y no se reutilice para una operación lógica diferente;
- `amount` sea una cadena que represente un entero positivo en unidades menores;
- `currency` sea la cadena `"604"` para operaciones en soles;
- todas las claves y valores de `additionalFields`, cuando se incluyan, sean cadenas.

## Datos de respuesta

| Dato | Disponibilidad | Uso de CELSAT |
| --- | --- | --- |
| `operationNumber` | En toda respuesta correlacionable. | Relacionar la respuesta con el evento del carril. |
| `transactionId` | Cuando Alignet haya asignado el identificador. | Soporte, seguimiento y conciliación. |
| `requestStatus` | En toda respuesta. | Distinguir recepción, validación, proceso, cancelación o finalización. |
| `result` | Cuando exista una decisión operativa. | Aplicar `PASS` o `NO_PASS` conforme a la política del carril. |
| `reasonCode` | Cuando el estado o resultado requiera una razón. | Diagnóstico y tratamiento funcional. |
| `amount` y `currency` | Cuando la solicitud haya sido reconocida. | Validar la operación correlacionada. |
| `brand` | Cuando se encuentre disponible y habilitado. | Comprobante y registro operativo. |
| `lastFourDigits` | Cuando se encuentre disponible y permitido. | Comprobante con dato enmascarado. |

## Interpretación de estados

  <Card title="Estado de solicitud" icon="signal">

  <Card title="Decisión de carril" icon="road-barrier">
    Usa `PASS` o `NO_PASS` cuando existe una decisión operativa válida.

Reglas de interpretación:

- una solicitud aceptada no equivale a `PASS`;
- un estado en proceso no autoriza a abrir la barrera;
- `PASS` no se deriva directamente de un código financiero aislado;
- un timeout o una respuesta ausente no equivalen a `NO_PASS`;
- un valor desconocido se registra sin asumir su semántica y activa el flujo de recuperación;
- `operationNumber` y `transactionId` son identificadores diferentes.

## Comprobante

CELSAT genera e imprime el comprobante. La respuesta puede proporcionar `operationNumber`, `transactionId`, estado, decisión operativa, razón, monto, moneda, marca y últimos cuatro dígitos cuando estos datos se encuentren disponibles y su uso esté permitido.

El formato y los campos mostrados se coordinan entre ambas partes y deben respetar las reglas de seguridad aplicables.
