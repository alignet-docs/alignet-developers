Usa `POST /reversals` para solicitar el **extorno total de una venta aprobada**. Conserva el `operationNumber` original.

## Cancelación y extorno

| Flujo | Uso | Verificación |
| --- | --- | --- |
| `POST /cancel` | Resolver una autorización en curso. CARD puede incluir un extorno interno si el cobro se aprueba durante la cancelación. En QR solicita cancelar la transacción pendiente; no extorna pagos aprobados. | Siempre `GET /payments/{operationNumber}`, incluso con HTTP `200`. |
| `POST /reversals` | Solicitar explícitamente el extorno de una venta aprobada. | `GET /reversals/{operationNumber}`, incluso con HTTP `200`. |

Sin solicitud de cancelación, un pago QR `APPROVED/00` se confirma; no requiere reversión por el solo hecho de estar aprobado. Después de solicitar cancelación, su resolución requiere el procedimiento QR separado.

Las [combinaciones de cancelación por método](/procesamiento-fisico/alignet-transit/cancelacion#resultados-por-m%C3%A9todo) no son resultados del extorno explícito.

## Requisitos por método

| Método | Requisito |
| --- | --- |
| CARD | Venta `APPROVED/00` y cobro vigente. Presenta la tarjeta cuando la solicite el PinPAD. Confirma durante certificación si la versión exige siempre la tarjeta original y los pasos de lectura. |
| QR | `/cancel` no ejecuta extornos. Revertir un pago aprobado requiere un procedimiento separado confirmado para QR; no presupongas soporte de `/reversals`. No aplica presentación de tarjeta. |

Antes del POST, verifica que no exista un extorno completado o en curso. Si no puedes comprobar el extorno interno CARD de una cancelación previa, concilia primero con Alignet. No generalices los requisitos de tarjeta del extorno explícito al interno de CARD.

## Solicitud

Envía al mismo host y puerto de la autorización:

```http
POST /reversals
Content-Type: application/json
```

```json
{
  "operationNumber": "44992528"
}
```

| Campo | Tipo | Obligatorio | Uso |
| --- | --- | --- | --- |
| `operationNumber` | String | Sí | Referencia original aceptada en la autorización; consulta [Parámetros](/procesamiento-fisico/alignet-transit/parametros-de-envio). |

No envíes monto, moneda, método ni datos de tarjeta. El extorno es total.

```bash
curl --request POST "http://<IP_DEL_PINPAD>:<PUERTO>/reversals" \
  --header "Content-Type: application/json" \
  --max-time 110 \
  --data '{"operationNumber":"44992528"}'

curl -i "http://<IP_DEL_PINPAD>:<PUERTO>/reversals/44992528"
```

Si recibes `Retry-After`, espera antes de consultar. La espera interna de desarrollo es de 90 segundos; el timeout de referencia del POST es de 100–110 segundos. Confirma valores definitivos por ambiente.

## Respuestas del POST

| HTTP | Resultado documentado | Acción |
| --- | --- | --- |
| `200` | `REVERSED` + `00` | Consultar el extorno y cerrar solo con resultado verificado. |
| `200` | `DENIED` | No registrar como extornado; consultar y conservar código y mensaje. No reintentar automáticamente. |
| `202` | `PENDING`, `WAITING_RESULT` | Respetar `Retry-After` y consultar; no duplicar. |
| `400` | `BAD_REQUEST` | Corregir el cuerpo. No es un rechazo financiero. |
| `404` | `NOT_FOUND` | Verificar referencia y terminal; no confirma ausencia de cobro. |
| `409` | `POS_BUSY` | Esperar a que termine la operación activa antes de reintentar la solicitud no aceptada. |
| `502` | `UNKNOWN` | Conservar evidencia y escalar; no reintentar en bucle. |
| `503` | `POS_NOT_AVAILABLE` | Restablecer disponibilidad y consultar antes de decidir otro envío. |

Respuesta de extorno aprobado:

```json
{
  "operationNumber": "44992528",
  "status": "REVERSED",
  "resultCode": "00",
  "resultMessage": "Extorno aprobado",
  "authorizationCode": "123456",
  "completedAt": "2026-08-27T20:30:00Z"
}
```

`00` aislado no basta. El ejemplo documentado de rechazo usa `DENIED/01` y mensaje `Extorno denegado`; el catálogo completo de códigos sigue pendiente.

## Consulta del extorno explícito

| HTTP de `GET /reversals/{operationNumber}` | Significado | Acción |
| --- | --- | --- |
| `200` | Resultado final como `REVERSED` o `DENIED`. | Evaluar estado y código; confirmar extorno solo con `REVERSED/00`. |
| `202` | Extorno en curso. | Respetar `Retry-After` y continuar consultando. |
| `404` | No existe solicitud registrada con esa referencia. | Verificar terminal y referencia; no deducir un resultado financiero. |
| `502` | Resultado `UNKNOWN` documentado. | Escalar con evidencia, sin reintentos en bucle. |

La autorización y el extorno pueden conservar registros separados. Encontrar `APPROVED` en `GET /payments/{operationNumber}` no confirma ni descarta el extorno. Tampoco está verificado que esta consulta de extornos exponga el extorno interno CARD de `/cancel`; sigue su [procedimiento de verificación](/procesamiento-fisico/alignet-transit/cancelacion#verificar-el-resultado-final).

## Estados del extorno

| Estado | Interpretación |
| --- | --- |
| `RECEIVED`, `SEARCHING` | Solicitud recibida o búsqueda de venta original; no final. |
| `PROCESSING`, `PENDING` | Extorno en proceso o espera HTTP agotada; continuar consultando. |
| `REVERSED` + `00` | Extorno aprobado; verificar por consulta. |
| `DENIED` | Rechazo confirmado; no extornado. |
| `UNKNOWN` | Requiere revisión según el punto del flujo. |
| `ERROR` | Evaluar HTTP, código y mensaje; no equivale a extorno. |

Durante la búsqueda de la venta, el `502 UNKNOWN` documentado significa que no se inició la reversa. Un reinicio durante su ejecución puede dejar `UNKNOWN` sin certeza de que el procesador la recibió. No generalices ambos casos como extornado o no extornado.

## Recuperación e idempotencia

- Ante timeout o desconexión, consulta la misma referencia: el timeout no determina el resultado financiero.
- Si el mismo extorno sigue en proceso, el POST devuelve `202`; si terminó, devuelve el resultado guardado sin repetir la acción.
- Otra referencia activa devuelve `409 POS_BUSY`. Serializa operaciones por terminal.
- No reenvíes en paralelo ni cambies el cuerpo. Consulta antes de cualquier reenvío permitido.
- No sustituyas un resultado final confirmado por un `PENDING` tardío ni inicies otra venta mientras falte resolución.

La ventana de extorno, ventas liquidadas, respuesta ante extorno previo, efecto contable y reflejo para el cliente requieren [confirmación](/procesamiento-fisico/alignet-transit/datos-por-validar).
