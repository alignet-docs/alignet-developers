El sistema central consume la interfaz HTTP/JSON que expone Pay-me PinPAD en el Wiseasy P5L. Construye todas las solicitudes a partir de la URL configurada para cada terminal:

```text
http://<IP_DEL_PINPAD>:<PUERTO>
```

El puerto predeterminado es `8080`. Confirma la IP y el puerto de cada terminal antes de integrar.

## Endpoints disponibles

| Método | Ruta | Uso | Respuestas documentadas |
| --- | --- | --- | --- |
| `GET` | `/health` | Verificar que Pay-me PinPAD esté accesible. | `200` |
| `POST` | `/authorize` | Iniciar CARD o QR; generar el QR crea la transacción pendiente. | `200`, `202`, `400`, `409`, `503` |
| `GET` | `/payments/{operationNumber}` | Consultar el cobro original. | `200`, `202`, `400`, `404` |
| `POST` | `/cancel` | Solicitar cancelar una autorización activa. | `200`, `202`, `400`, `404`, `409`, `503` |
| `POST` | `/reversals` | Solicitar un extorno explícito de una venta CARD aprobada. No aplica a QR. | `200`, `202`, `400`, `404`, `409`, `502`, `503` |
| `GET` | `/reversals/{operationNumber}` | Consultar el extorno CARD. | `200`, `202`, `400`, `404`, `502` |

<Note>
  `POST /cancel` y `POST /reversals` son operaciones distintas. Ambas usan el `operationNumber` de la autorización original y se consumen en el mismo host y puerto que `POST /authorize`.
</Note>

No existe un endpoint de consulta de cancelación. Su desenlace se devuelve solo en `POST /cancel`; `/payments` consulta el cobro original. Todas las respuestas incluyen `Cache-Control: no-store` y HTTP `202` añade `Retry-After: 2`.

## Verificar disponibilidad

```http
GET /health
```

```bash
curl "http://<IP_DEL_PINPAD>:<PUERTO>/health"
```

Respuesta esperada:

```json
{
  "status": "UP",
  "service": "Alignet ECR"
}
```

Usa `GET /health` al configurar el terminal y antes de iniciar operaciones cuando necesites comprobar disponibilidad. Una respuesta satisfactoria confirma la aplicación local; no confirma por sí sola que el procesador aprobará pagos.

## Autorizar y consultar un pago

`POST /authorize` requiere un cuerpo JSON. Consulta [Solicitud de autorización](/procesamiento-fisico/alignet-transit/parametros-de-envio) para conocer los campos, las validaciones y los ejemplos.

`GET /payments/{operationNumber}` no lleva cuerpo. Usa exactamente la referencia enviada en la autorización:

```bash
curl -i "http://<IP_DEL_PINPAD>:<PUERTO>/payments/44992528"
```

## Cancelar una autorización activa

`POST /cancel` recibe el `operationNumber` original. Reconoce cancelación exitosa solo con `CANCELLED` y `00`, `16` o `17`, validada por el servicio. HTTP `200` con `DENIED`, incluido `14`, no confirma éxito.

Ante fallo, timeout o incertidumbre, consulta el cobro original; no hay un GET de cancelación. El cierre de pantalla no acredita el resultado. Revisa las [respuestas y acciones de cancelación](/procesamiento-fisico/alignet-transit/cancelacion).

En QR solo se cancela o inhabilita el código; ni `/cancel` ni refund devuelven pagos. Un QR `APPROVED/00` conserva el pago aprobado, sin reversa.

## Extornar una venta aprobada

`POST /reversals` solicita un extorno independiente y total de una venta CARD aprobada. No aplica a QR. Usa `GET /reversals/{operationNumber}` ante espera, timeout o pérdida de respuesta. Encontrar el cobro original no determina el resultado del extorno.

Consulta [Extorno de una venta CARD aprobada](/procesamiento-fisico/alignet-transit/extorno) para interpretar `REVERSED`, `DENIED` y el cuerpo compacto de `502 UNKNOWN`.

## Rutas fuera del contrato vigente

Una ruta válida con método incorrecto devuelve HTTP `405` y `METHOD_NOT_ALLOWED`; una ruta desconocida devuelve HTTP `404` y `NOT_FOUND`.

No uses `/payment`, `/api/v1/payments`, `/api/v1/payments/{operationNumber}` ni `DELETE /charges` para esta integración. Tampoco diseñes el cliente alrededor de una respuesta anidada en `result.state`, los códigos locales `P01–P21` o campos como `transactionID`: pertenecen a especificaciones anteriores o a otros productos.
